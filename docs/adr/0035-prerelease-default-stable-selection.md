# ADR-0035: Select a GA release when deps.dev defaults to a prerelease

Date: 2026-11-14
Status: Accepted

## Context

ADR-0023 rule 3 selected deps.dev's newest `isDefault` version without checking its stability. This made a prerelease the Stable version even when the package had published GA releases. Stable anchors the version used for licenses, advisories, lifecycle analysis, the GitHub-URL versioned PURL, and usually repository and Scorecard lookup. deps.dev's `publishedAt` can reflect indexing time, so it is not a reliable ordering for GA releases. For example, Spring Boot 4.1.x can be higher than a later-published 3.5.x maintenance patch; JavaFX GA releases can have timestamps seconds apart.

## Decision

Keep ADR-0023's PyPI registry hint exact match and PEP 440 bound ahead of the deps.dev fallback, and keep ADR-0024's cargo withdrawal filter. In the fallback, classify the deps.dev default and GA candidates for Stable selection. The system is the case-insensitive PURL type in `VersionKey.System`: `maven`, `npm`, `cargo`, `pypi`, or `golang`. Maven and Go defaults use the PURL-type-aware `purl.IsStableVersionFor` heuristic. npm and cargo additionally require an empty SemVer prerelease when parseable; PyPI additionally requires a non-prerelease PEP 440 version when parseable. A failed npm/cargo/PyPI parse falls back to the heuristic. Max and the PyPI bound are unchanged.

A stable default stays Stable. If a default in one of these five systems is unstable, choose the highest eligible GA across all versions, including GA above the default; if none exists, keep the default. Exclude candidates with deps.dev `IsDeprecated=true` from this override in every system. Require Go override candidates to parse as SemVer with an empty prerelease, which also excludes pseudo-versions. This prevents an untagged commit or a keyword-free prerelease tag such as `v2.0.0-next.3` from replacing a tagged prerelease instead of a GA release. These candidate checks do not filter Dev or Max candidates and do not change Go's default classification or the no-default fallback; the replaced-default Dev rule below applies after an override. Other PURL types retain their default-first behavior because this decision has no reviewed release-order or prerelease semantics for them.

When an override happens and Stable's repository resolution does not yield GitHub, resolve the replaced default's repository too. Prefer its GitHub URL when available; if Stable has no repository URL, retain any non-empty repository URL from the replaced default. Keep Stable's GA PURL for version-linked data. See the ApacheDS consequence below.

ADR-0024 rejected filtering Stable on `isDeprecated` alone because that would conflate withdrawn and merely deprecated releases. This decision only declines to substitute a deprecated GA during the unstable-default override: it never removes the default or a PyPI-bound selection for mere deprecation, while ADR-0024's cargo yank filter still applies. A cargo release with an unknown deprecation reason is not withdrawn under ADR-0024, but it is skipped as an override candidate here.

When no default exists, Maven, npm, cargo, and PyPI choose the highest eligible GA by version order if one exists. Otherwise they retain the prior latest-`publishedAt` heuristic-stable fallback; this preserves a Stable value for npm/PyPI strings that only the ecosystem parser identifies as prereleases. Go and other systems always retain that old no-default fallback, including heuristic-stable Go pseudo-versions.

Dev normally remains the latest version that `purl.IsStableVersionFor` calls unstable, ordered by `publishedAt`. When an unstable-default override selects a GA, retain the replaced default as Dev if the heuristic Dev is empty or older by `publishedAt`. This preserves the recent-prerelease activity signal for a default such as npm `2.0.0-next.4` that only the ecosystem parser identifies as a prerelease. A newer heuristic Dev still wins; the no-default path is unchanged.

Rank eligible GA by the existing SemVer comparator if every npm/cargo/Go candidate parses, or the existing PEP 440 comparator if every PyPI candidate parses. Otherwise use one transitive ordering for every candidate: presence of a leading numeric core (after optional `v`), non-date numeric core before date-form numeric core, then dotted numeric components, then `publishedAt`, then raw version string. A leading numeric component of eight or more digits is date-form and ranks below every other numeric version; date-form versions retain the same ordering among themselves. This applies to the override and no-default selection. A numeric version outranks `r09`; `3.20.0.Final` is ordered by its numeric core, while `20030203.000550` cannot displace `3.2.2`. The final tie-break removes input-order dependence. No new dependency is needed.

For Maven PURL types only, extend the shared heuristic to bounded `M<n>`, `AM<n>`, `CR<n>`, and `ea` (optional digits) tokens. The left boundary is the start, `.`, `-`, or `_`; the right boundary is the end, `.`, `-`, `_`, or `+`. Ignore build metadata after `+` when checking all instability keywords. A name-like segment such as `featureAM2` stays stable under the new token rule. A version such as `0.11.0+wasi-snapshot-preview1` changes from unstable to stable: it leaves Dev, and the integration `IsPrerelease` flag changes from true to false. The build-metadata rule affects all types; Maven qualifier tokens also affect non-SemVer Maven dependency probe ranking and integration prerelease flags. Go pseudo-version hashes resembling an `ea` token remain stable under the shared heuristic.

## Consequences and limits

`apacheds-core` has GA 1.0.0–1.5.7, followed by a prerelease-only 2.0.0 line from M1 in 2011 to default AM27 in 2023. The issue's exception applies to packages that have only ever published prereleases, so it does not apply here or to the similarly shaped `apacheds-core-api`. Stable is 1.5.7; AM27 remains Dev/PreReleaseVersion. Licenses, advisories, and the GitHub-URL versioned PURL anchored to Stable use 1.5.7. Before the repository safeguard, the runtime changed from AM27's GitHub repository (score 6.3, Stalled) to 1.5.7's SVN `SOURCE_REPO` (score 0, EOL-Effective). The repository is now kept from the replaced default when it resolves to GitHub. The recent-prerelease signal still sees AM27. Its 2023 publication is already outside the 365-day recent-stable window, so this package's recent-stable outcome does not change. More generally, moving Stable to an older GA can cross the 365-day recent-stable and 180-day recent-prerelease windows and change the advisory version read by inactive-path and residual-vulnerability rules, so the lifecycle label can change: a 400-day-old GA with a 200-day-old prerelease default and no recent human commits can move from active to inactive. This is consistent with ADR-0023's PyPI path, where `info.version` supplies the newest GA regardless of its age.

When Scorecard or commit data is unavailable, Maintained is low, or the last commit is older than 730 days, the newest GA's dependency graph can still decide between Stalled and EOL-Effective, as it already did for packages whose Stable was GA before this change.

A version its registry marks deprecated is not one new users are steered to, so the override does not substitute it as Stable and retains the default if all GA candidates are deprecated. Additionally, a deprecated Stable can trigger the deps.dev-deprecated EOL rule for Go or npm's registry stable-deprecation rule; when deps.dev does not report deprecation, the npm registry rule still evaluates the selected GA. deps.dev rarely reports deprecation for Maven and PyPI, so this skip chiefly affects npm, Go, and cargo releases with a non-yank deprecation reason.

An age exception would rely on deps.dev index timestamps; a major-version-gap exception cannot distinguish ApacheDS from Quarkus or Elytron. Unknown Maven qualifier names such as `-next` can still evade the heuristic. The no-proxy Go module path's existing double escape is outside this decision.
